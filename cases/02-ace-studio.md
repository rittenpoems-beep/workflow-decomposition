# 当工具是对的，作品仍然不对

**案例 02｜ACE Studio 音乐实验，与「冒烟测试通过」之后的失败**

这是整本册子里最不体面的一个案例，也是最有用的一個。

它证明了一件事：**当所有局部检查都通过时，你仍然可能没有得到一件愿意拿出去的作品。**

## 一句话结论

ACE Studio 不是这次失败的根本原因。真正的问题在更上游：

1. **类型与参照没有被写成可验收的标准**，只在出问题后靠耳朵返工；
2. **旋律、段落与咬字是三个独立的验收维度**，却长期被「文件生成成功」掩盖；
3. **没有停止条件**，于是一次次在既定路线上修补，而不是重新比较路线；
4. **工具的局部合理性，被误当成了整条路线的合理性。**

## 两次实验，一条升级路径

### 第一次：15 秒抖音向 BGM

主题「傲慢与嫉妒」，目标是一段可卡点的短视频 BGM。

最终交付：

| 维度 | 结果 |
|---|---|
| 时长 | 15.36 s |
| BPM | 140.625 |
| 调性 | C 小调 |
| 小节 | 9 小节 4/4 |
| 分轨 | 21 条 |
| 母带 | −9.18 LUFS / 真峰 −1.13 dBTP / LRA 1.5 |
| 频谱重心 | 2529.8 Hz（参考 2497.6 Hz） |

这条链路是采样 MIDI 路线：Python 写谱 → MIDI → FluidSynth 采样渲染 → Python DSP 混音 → 母带。代码、MIDI、分轨、成品与分析数据都公开在 [`ritten-musicByAI`](https://github.com/rittenpoems-beep/ritten-musicByAI)。

它通过了验收，因为它的目标很窄：**对齐一首参考 BGM 的类型、时长、节拍与频谱，而不是成为一首可发行的歌。**

试听：[15 秒成品](../site/assets/audio/pride-envy-15s.mp3)（CC BY 4.0）

### 第二次：BoyWithUke 风格完整歌曲

这次的目标高得多：不是「一段能听的音频」，而是一首按 BWU 早期风格写的、有人声、有结构、能进入发行语境的歌。

先做了一件之前没做的事：把 2021–2026 六张专辑的 **40 首官方曲目**全部过了一遍，形成 `BWU_GRAMMAR.md`。关键统计：

- 中位速度 **99.4 BPM**，中位时长 **189 s**，中位 **7 段**；
- 全语料 **152 个 verse 段，只有 33 个 chorus 段**：长主歌、晚副歌、短尾奏；
- 段落 RMS：intro −23.3、verse −19.6、chorus −17.1、bridge −17.2、outro −16.7 dB；
- chorus 比 verse 高约 **+2.5 dB**，但 20–60 Hz 反而低约 **7 dB**：副歌不是靠 sub 顶上去的；
- bridge 是「换质地」：250–500 Hz 突出、低频退后；
- outro 起音密度最低（2.29/s），伴奏继续响、人声先停；
- Demucs 分轨里 bass 是最响的 stem，人声活跃占比 70–82%，鼓是半速、稀疏的编程鼓。

这些数字后来变成了编配规则，也变成了验收标准。

最终产物：

| 维度 | 结果 |
|---|---|
| 音乐时长 | 3:04.2（文件 3:07.2，保留尾音） |
| BPM | 99 |
| 调性 | B 小调（谱面按 F# 小调写，整体 +5 移调） |
| 小节 / 段 | 76 小节 / 9 段 |
| 编制 | 12 轨真实采样 bed + 7 轨 ACE 人声 |
| 人声 | Lead、双 L/R、高和声、低和声、耳语、adlib |
| 定版混音 | −13.19 LUFS / 真峰 −1.5 dBTP（该轮） |

## 冒烟测试：全部通过

如果只看自动化检查，这次实验是成功的：

- 音频文件生成成功，时长、格式、采样率正确；
- 7 条人声分轨全部导出，ACE 工程可以保存、重开；
- 混音、母带、频谱分析、段落电平分析全部跑通；
- Whisper 转写能读出一部分歌词；
- 段落电平、低频占比、人声与伴奏的差值都有量化报告；
- 乐谱、歌词、构建脚本、导出文件都在。

这正是「冒烟测试」的典型状态：**系统没有立刻坏掉，而且看起来越来越完整。**

## 完整验收：五个维度逐个失败

### 1. 类型：从「古典」到「像但假」

第一版是一首 2 分 47 秒的古典 tone poem。技术指标正常，但用户的判断很直接：

> 「你这个太古典了，不是抖音年轻人喜欢的类型。」

第二版改为 BWU 风格，仍然被否：

> 「有一点一言难尽，和 BWU 本人的风格差得太远了。」

第三版：

> 「有一种刻意想学但是学得非常糟糕的感觉……类比就是一个虚荣的农民想学有钱人打高尔夫，然后举着锄头打卷心菜。」

问题不在音色库，也不在混音。是**类型骨架**错了：v2 是 104 BPM 的正拍流行歌，BWU 是 89 BPM 的半速 emo 卧室流行；v2 的人声连成 1.27 秒的长句，BWU 每 0.22–0.52 秒就断一次，每秒 3–4.7 个字。

后来把咬字改成半说半唱的八分音符，每秒咬字从 0.65 提升到 2.87，才进入参考区间的下沿。

### 2. 结构：outro 比 chorus 低 10 dB

第一次完整混音后，结构对照发现：

- **outro 比 chorus 低近 10 dB**，而语料里 outro 几乎和 chorus 一样响；
- **bridge 低 3 dB**。

这不是混音推子的问题，是编配问题：outro 被写成了「淡出」，而不是一个真正的收束段。补上持续 pad、strings、piano、低音与最后一下 kick/crash 后，段落弧线变为：

- verse 比 chorus 低 2.2 dB；
- bridge 低 0.8 dB；
- outro 低 3.0 dB。

### 3. 旋律：只跨 5 个半音

这是最根本的问题之一。

当前主旋律只跨 **5 个半音**，**89% 是级进**；而 40 首 BWU 语料的中位跨度是 **17 个半音**，**16% 是跳进**。这就是「人声差」的核心原因之一：不是音色不够好，是旋律本身没有流行旋律的起伏。

重写后：

- 音域 **19 个半音**；
- p5 / 中位 / p95 = 54 / 62 / 67；
- 级进 37%、三度 20%、跳进 16%、重复 27%；
- 与 40 首语料的统计画像一致。

### 4. 咬字：G2P 把英文唱错了

ACE 的 G2P 暴露出真正的发音错误：

| 歌词 | 被唱成 |
|---|---|
| every | ev-eh |
| memorized | o 唱成「oh」 |
| permission | sion 唱成「sigh」 |
| stop | sdop |
| score | sgor |
| quiet | kwee-et |

多音节词（memorized、editing、permission、blurry、read-through）整体含混。逐音符改音素后，hook 整句可辨；但新的问题出现了：

- 副歌整体升高后，人声在 **A4** 附近咬字明显变差；
- 把最高点从 A4 降到 F#4/G4 后，仍需把副歌与桥段整体下移 **2–4 个半音**；
- 优先保证「听得懂」，再谈最高音。

### 5. 混音：高潮被自己盖住

- 第二遍副歌里，人声只比伴奏高 **0.4 dB**，高潮被伴奏压住；
- 把末副歌人声再抬 2.5 dB、伴奏让 1.3 dB 后，Whisper 仍然捕捉不到 2:20–2:38 的人声；
- 真正的原因不是混音，而是**末副歌第 58–63 小节的主唱轨被一次尾音边界编辑弄成了静音**；
- 回退时序后恢复有声；局部增益又把末副歌推得过猛（+7.1 dB），主歌反而被压到伴奏下面；
- 最终撤掉局部增益，整体人声抬 2.4 dB，段落关系回到：主歌 +2.1 dB、副歌 +3.5 dB、末副歌 +6.5 dB。

至此，段落弧线、咬字、旋律、编制都「修好了」。

然后用户听完，说：

> 「听起来很诡异，我下来再自己研究吧，先做到这里。」

这句话是完整验收的终点。**所有指标都合格，但没有人愿意把它当作作品发布。**

2026-10-20，用户决定终止实验，删除工程文件与下载的参考歌曲。公开的 15 秒作品仓库保留。

## 关于 ACE Studio 的那次回答

文章里写到过一次对话：用户问 AI，要不要换掉 ACE Studio，AI 回答说没必要。

实际记录比文章里的一句话更复杂。当时的完整回答是：

> 「现在别删。ACE 的声音引擎是专业的，问题出在 CLI 还是 0.17.0 预览版——偶发合成失败、音素时序接口很原始，调试成本高，但它是目前链路里唯一能逐音素控制英文演唱的引擎。剩下的短板主要是『声线模型的咬字』，换软件未必解决，换更好的声线或授权歌手声线更直接。真要换，Synthesizer V 的英文咬字更稳，但没有同等成熟的 CLI，接入成本高；Suno/Udio 不可控，DiffSinger 要自己训练。建议留到这首定稿后做一次 A/B，再决定。」

这段话本身没有错。它甚至列出了替代路线和迁移成本。

但它仍然暴露了一个更深的问题：**它回答的是「ACE 专不专业」，而不是「在当前交付物与验收标准下，这条路线是否值得继续」。**

- ACE 的引擎是专业的，不代表这个**混合声线**能唱清英文；
- 能逐音素控制，不代表逐音素修补是划算的；
- 换软件未必解决，不代表「不换软件 + 继续修补」就是正确路线；
- 建议「定稿后再 A/B」，但定稿的前提是这一版能通过验收——它没有。

所以，文章里的那句话可以更精确地写成：

> AI 对工具的肯定，可能建立在真实的局部验证之上；但局部验证回答不了路线问题。

这不是 ACE Studio 的失败。它是**路线级验收缺位**的失败。

## 如果重来，会在哪里设闸门

### 闸门 1：类型与参照（写歌之前）

- 选定 3 首参考曲，写下每一首的 BPM、半速/正拍、段落数、人声断句、鼓的密度；
- 用一段 15 秒的 mockup 先验证类型，而不是先写 76 小节；
- 如果 mockup 不像，停止编曲，不要用混音去救。

### 闸门 2：旋律轮廓（编曲之前）

- 统计音域、级进/跳进比例、重复率；
- 与语料的分位数对照；
- 不通过就不进入配器。

### 闸门 3：人声路线（写旋律之前）

先决定人声怎么来：

- 授权真人歌手；
- 更成熟的英文合成声线（如 Synthesizer V）；
- ACE 的某一条具体声线，先用一句话测试咬字，再决定是否用于整首。

**不要先写完歌，再发现声线唱不清。**

### 闸门 4：段落弧线（混音之前）

- 用与语料相同的口径测 verse / chorus / bridge / outro 的电平；
- 先改编配，再动推子；
- 不通过就不进入母带。

### 闸门 5：人的试听（交付之前）

- 盲听 30 秒，能否说出这是什么类型、情绪是什么、hook 是哪一句；
- 愿不愿意把它发给别人听；
- 如果不愿意，指标再好也不交付。

## 可复用的结论

- **冒烟测试通过，只说明「没有立刻坏掉」。** 文件存在、指标正常、转写可读，都不等于作品成立。
- **类型错误不能靠混音修复。** 先对齐参考的类型骨架，再谈音色与响度。
- **旋律是被最容易忽略的验收维度。** 音色、混音、母带都可以很专业，但 5 个半音的旋律仍然不像一首流行歌。
- **工具的专业性，不等于路线的正确性。** 路线要按交付物与验收标准判断，而不是按工具的功能表判断。
- **要有停止条件。** 如果连续两轮完整验收都失败，应该重新比较路线，而不是继续在既定路线上加补丁。
